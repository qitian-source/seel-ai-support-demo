Seel Compass — Phase 1（店铺政策扫描）PRD
本期落地范围 · 爬取线 only · 对应主 PRD v1.3 / registry
本文档目的：把 Phase 1 收敛到只做店铺政策相关扫描（爬取线）、不接任何外部数据库。这是为了赶 7 月上线、去掉外部集成的关键路径。完整 5 类目愿景、状态机、生产架构见主文档：中文 PRD · 法务英文 PRD · Rule Citation Registry。

模块数据源本期

一句话：本期只做"爬公开店面 + 内部规则 corpus"就能完成的检查，零外部数据库接入。IP 与 Corporate Entity 因为要接外部库（成本 / ToS / 集成周期），推迟到紧接的 fast-follow —— 是分期，不是砍，5 类目愿景不变。

2. 为什么这么切

  • 砍掉唯一的两个外部集成 —— USPTO（2–3 周）+ Middesk（1 周 + ~$10/lookup + 自动查询州门户的 ToS 法律问题），全部移出关键路径
  • 运行时外部调用归零 —— 系统简化为纯"爬取 → corpus 查表 → 渲染"，这条 pipeline 已 built
  • 一点不丢 Michael 7/17 扩充 —— 他新增的 12 条检查全在 D&P / T&C / Product，没有一条是 IP/Entity；砍这两个模块，政策扫描深度反而是加厚的
  • 赶 7 月 —— 关键路径上不再有外部集成，剩下都是自有 pipeline + corpus 的活

3. 三个模块做什么

检查集以 registry 为唯一真源（含 Michael 7/17 扩充的 12 条；⊕ = 新增、研发未建）。概览：

模块覆盖示例
🔒 Data & Privacy隐私政策存在性阈值检查 ⊕ · 访问/删除/可携权 · lawful basis · cookie 先于同意 · DSAR 窗口 · 撤回同意 · Do-Not-Sell 链接 ⊕ · GPC 通用 opt-out ⊕ · COPPA 儿童数据 ⊕ · 跨境传输披露 ⊕
📄 Terms & Conditions条款存在性阈值检查 ⊕ · governing law 条款（描述性）· 无限定担保 · 退款窗口 · EU 电子撤回功能 ⊕ · 14 天撤回权 ⊕ · 商家身份披露 ⊕ · 与 EU 不可放弃权利冲突 ⊕ · 仲裁/弃权条款存在（描述性）⊕
🛍️ Product受管制品类检测（酒精/CBD/烟草/枪械/补剂/药品，仅检测不下结论）· 健康/功效声明 · 原产地 · 绿色声明 · 参考价 · 儿童玩具安全 · Responsible Person · INCI · Prop 65 · 危险品 · 背书披露 · 紧迫性声明 · 网站可访问性（三态）⊕

4. 系统（本期）

  • 单一管线：爬取店面 + 证据存储 → 引擎（LLM 只输出 rule_id + 判定 + 证据，不写引用）→ 渲染（rule_id 查 registry 拼引用）→ 报告。零运行时外部调用。
  • 引用只渲染、不生成（硬约束）：商家看到的每条引用都来自 counsel 签署的 registry；模型运行时永不产生法条引用。
  • 架构细节（registry = 版本化文件、签署 = PR、grounding CI 门、证据存储）见主 PRD §14，本期不变。

6. 法务保障（沿用，不变）

Phase 1 完整沿用主 PRD §5 的全部保障，本期无新增例外：

  • 语言红线（never violates / illegal / non-compliant / deceptive）· 每条 review item 以"建议咨询律师"结尾
  • 四态：Verified / Review Item / Not Assessable / N/A（含描述性、三态检查的呈现约定）
  • Source & Proof 层（引用 chips + 解释依据标签 + corpus 版本 + 页面证据/缺席证明）
  • Onboarding 前置 counsel 版免责声明 · 授权勾选 + DNS 域名验证
  • Self-harm scope-out（Seel 自家产品相关规则整体不在方法论内）

8. 本期验收（关键项）

  • D&P / T&C / Product 三类目能对测试商家产出 Verified / Review / Not Assessable 三态 finding
  • 每条引用来自 registry 查表；运行时模型生成引用次数 = 0（CI 硬检查）
  • 商家 UI = 4 tab / 4 分数卡；无 IP、无 Entity tab

9. 明确推迟到 fast-follow

  • Corporate Entity（Middesk / 州 SoS good-standing）—— 接外部 API + 实体问卷
